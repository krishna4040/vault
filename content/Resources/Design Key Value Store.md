# What is a Key Value Store?

- **Key-value stores** are distributed hash tables (DHTs)
- A key is generated by the hash function and should be unique
- A value can be a blob, image, server name, or anything the user wants to store against a unique key

# GET and PUT

$R + W > N$

R means the minimum number of nodes that need to be part of a successful read operation while W is the minimum number of nodes involved in a successful write operation

![[System/Assets/mz1wyem1.bmp]]

## PUT(CAR)

1. Find hash value i.e. key for CAR
2. Update the value in coordinator node and W replica nodes in sync manner
3. Update the value in subsequent node in async manner
4. Coordinator waits for W Replicas nodes in order to send back success status

## GET(CAR)

1. Generic Load balancer → Hopping with high latency
2. Partition aware Load balancer → Hopping with Low latency

The serving node from the preference list will wait for R replicas Nodes and send data as success

# Data versioning

When failure happens, there may be different version of the same key

We maintain a **vector clock or Counter.**

Last write win algorithm is used to resolve conflict

![[System/Assets/2hbvlnzu.bmp]]

## Limitations

- The size of vector clocks may increase if multiple servers write to the same object simultaneously
- we can have a long version like this: (\[𝐴,10],\[𝐵,4],\[𝐶,1],\[𝐷,2],\[𝐸,1],\[𝐹,3],\[𝐺,5],\[𝐻,7],\[𝐼,2],\[𝐽,2],\[𝐾,1],\[𝐿,1])(\[_A_,10],\[_B_,4],\[_C_,1],\[_D_,2],\[_E_,1],\[_F_,3],\[_G_,5],\[_H_,7],\[_I_,2],\[_J_,2],\[_K_,1],\[_L_,1])
- We employ a clock truncation strategy to store a timestamp with each (node, counter) pair to show when the data item was last updated by the node
- Vector clock pairs are purged when the number of (node, counter) pairs exceeds a predetermined threshold (let’s say 10)

# Gossip protocol

Each server maintains a membership list, at a random period they send a heartbeat and some meta data like range of keys they are maintaining so that they know how many servers are up and down in a distributed system.

# Merkle Tree

In a **Merkle tree**, the values of individual keys are hashed and used as the leaves of the tree

The Merkle tree is a mechanism to implement anti-entropy, which means to keep all the data consistent. It reduces data transmission for synchronization and the number of discs accessed during the anti-entropy process
